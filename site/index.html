USB direct · nothing in the middle

Move files and text between your computer and an Android phone over one USB cable.

No network. No cloud. Nothing to install on the phone. Plug the cable in, open a page on the phone, and both directions work.

How it works

One Go binary. The cable is the whole transport.

Phone browser or APK
adb reverse tcp:8765 USB cable
Computer 127.0.0.1:8765 · Go HTTP
  • The computer listens on 127.0.0.1 only. No firewall prompt, nothing on the LAN.
  • The frontend is plain HTML/CSS/JS embedded with go:embed — no npm, no build step.
  • The clipboard goes through the page, not adb shell: Android 10+ forbids writing the device clipboard over adb, and localhost is a secure context, so the browser Clipboard API works there.
  • Device presence rides a persistent adb track-devices connection — no process forking while idle.
  • Icons are drawn in code by a small in-process rasteriser. There is no binary artwork in the repository.

What's in the box

Send and receive files

Drop files or whole folders on the panel; pushes land in the phone's Download folder. Pulls land in the shared folder on the computer.

Clipboard bridge

Both directions, including a dedicated note slot so sending text never overwrites the clipboard you're working from.

Phone file browser

The shared folder on the computer is a real file browser on the phone — subfolders, sizes, downloads included.

Honest progress

Byte-weighted percentages, elapsed time when adb offers nothing, and failures reported in words rather than error codes.

Real connection states

Not connected, connecting, cable in the wrong USB mode, adb missing, tunnel failed — each says what to do next.

Optional Android app

A ~845 KB WebView shell for when you want it to feel installed: real file picking, downloads into the Downloads app, a reconnect screen.

Light and dark

Both surfaces follow prefers-color-scheme. It is a media query, not a setting.

Portable build

macOS, Windows and Linux from one tree. Windows cross-compiles from a Mac; the Linux build needs GTK3 and WebKitGTK 4.1.

The Android app is optional

Everything above works in the phone's own browser — nothing to install. The APK is a small WebView shell around the very same page, for when you would rather tap an icon than a bookmark. It bundles no server of its own: plug the cable in exactly as before.

Launcher icon — the same artwork as everywhere else, drawn in code rather than shipped as bitmaps.

  • File picking that behaves. Uploads use the system picker, and downloads land in the Downloads app with non-ASCII names intact.
  • A reconnect screen. Cable out says so plainly instead of showing a WebView error.
  • A themed window. The window background and status bar follow the system light/dark setting, so a dark phone never flashes white on cold start.

Run it yourself

  1. Get adb. Install Android Platform Tools (brew install android-platform-tools), or drop the platform-tools folder next to the binary.
  2. Build. 
    make app          # CableDrop.app — a menu bar app, no Dock icon
open CableDrop.app
  3. Plug in the cable and set the phone's USB mode to File transfer / MTP. "Charging only" is invisible to adb.
  4. Open the panel from the menu bar, then open http://localhost:8765 on the phone. That's the whole phone UI.
